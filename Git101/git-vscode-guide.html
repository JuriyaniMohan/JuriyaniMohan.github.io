Git Workflow in VS Code
The complete edit → commit → push → PR loop, step by step.
01
Clone the Repository
Start by cloning the remote repo to your local machine. Open VS Code's integrated terminal with Ctrl+` and run:
$ git clone https://github.com/user/repo.git
$ cd repo
💡 You can also use Ctrl+Shift+P → "Git: Clone" to clone directly inside VS Code.
02
Pull Latest Changes
Always sync before starting work to avoid merge conflicts later.
$ git pull origin main
💡 Use the Source Control "…" menu → Pull, or click the sync icon in the status bar (bottom-left).
03
Create a Feature Branch
Never work directly on main. Create a branch for your change — keeps history clean and enables proper code review.
$ git checkout -b feature/add-monitoring-playbook
💡 Click the branch name in the bottom-left status bar → "Create new branch" for a GUI approach.
04
Edit Your Files
Make your changes. VS Code marks files in the Explorer with colour-coded badges:
M — Modified U — Untracked (new) D — Deleted R — Renamed
05
Stage Changes
Staging tells Git exactly which changes to include in the next commit. You can be selective.
# Stage specific file
$ git add playbooks/monitoring.yml

# Stage everything
$ git add .
💡 In the Source Control panel (Ctrl+Shift+G), click the + icon next to each file to stage it individually.
06
Commit with a Clear Message
Write a concise, descriptive commit message. Use present tense, explain the "what" and "why".
$ git commit -m "Add Prometheus alerting rules for disk usage"
💡 In VS Code, type your message in the Source Control input box and press Ctrl+Enter to commit.
07
Push to Remote
Send your branch to GitHub so others can see it and you can open a PR.
# First push — set upstream tracking
$ git push -u origin feature/add-monitoring-playbook

# Subsequent pushes
$ git push
08
Create a Pull Request & Merge
Go to GitHub — you'll see a banner to create a PR. Add reviewers, get approvals, then merge. After merge, clean up locally:
$ git checkout main
$ git pull origin main
$ git branch -d feature/add-monitoring-playbook
💡 Install the GitHub Pull Requests extension to create, review, and merge PRs without leaving VS Code.
Common Issues & Fixes
Click any issue to expand the solution. All fixes tested in real-world scenarios.
ERROR Permission denied (publickey)
▾

SSH authentication failed. Your SSH key is missing, not added to the agent, or not registered on GitHub.

✓ Solution
# Generate a new SSH key
$ ssh-keygen -t ed25519 -C "you@email.com"

# Start the SSH agent and add the key
$ eval "$(ssh-agent -s)"
$ ssh-add ~/.ssh/id_ed25519

# Copy public key → add to GitHub → Settings → SSH Keys
$ cat ~/.ssh/id_ed25519.pub
ERROR Merge Conflicts
▾

Two branches modified the same lines. Git can't auto-merge and marks the conflicting sections.

✓ Solution

VS Code highlights conflicts inline with clickable options: Accept Current | Accept Incoming | Accept Both. After resolving all conflicts:

$ git add .
$ git commit -m "Resolve merge conflict in config.yml"
WARN Detached HEAD State
▾

You checked out a commit hash or tag instead of a branch. Commits made here will be lost unless saved to a branch.

✓ Solution
# Create a branch from current detached state
$ git checkout -b recovery-branch

# Or go back to an existing branch
$ git checkout main
ERROR Rejected Push (non-fast-forward)
▾

Remote has commits you don't have locally. Git refuses the push to prevent overwriting others' work.

✓ Solution
# Pull and rebase your changes on top
$ git pull --rebase origin main

# Then push again
$ git push origin main
WARN Accidentally Committed to Main
▾

You made commits directly on main instead of a feature branch.

✓ Solution
# Create a new branch with your commits
$ git branch feature/my-work

# Reset main to match remote
$ git reset --hard origin/main

# Switch to your feature branch
$ git checkout feature/my-work
INFO Undo Last Commit (Keep Changes)
▾

You committed too early or with a wrong message. Want to undo the commit but keep files as they are.

✓ Solution
# Undo commit, keep changes staged
$ git reset --soft HEAD~1

# Undo commit, keep changes unstaged
$ git reset --mixed HEAD~1
WARN Large File Rejected by GitHub
▾

GitHub blocks files over 100 MB. Even if removed later, the file persists in Git history.

✓ Solution
# Add to .gitignore going forward
$ echo "*.iso" >> .gitignore

# Remove from history (use git-filter-repo)
$ git filter-repo --path bigfile.iso --invert-paths

# For large files, use Git LFS
$ git lfs track "*.iso"
ERROR fatal: not a git repository
▾

You're running Git commands outside a repo directory, or the .git folder was deleted.

✓ Solution
# Navigate to the correct directory
$ cd /path/to/your/repo

# Or initialize a new repo
$ git init
INFO Stash Work to Switch Branches
▾

You have uncommitted changes but need to switch branches urgently (e.g., hotfix).

✓ Solution
# Save current work
$ git stash push -m "WIP: monitoring playbook"

# Switch and fix
$ git checkout hotfix/urgent-patch

# Come back and restore
$ git checkout feature/monitoring
$ git stash pop
