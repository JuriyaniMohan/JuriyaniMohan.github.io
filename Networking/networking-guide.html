Chapter 01

What Is an IP Address?

What Is It?

An IP address (Internet Protocol address) is a unique numerical label assigned to every device connected to a network. Think of it as a postal address for your computer — without it, no data can be delivered to or from your device.

There are two versions in use today:

FeatureIPv4IPv6
Format192.168.1.102001:0db8::1
Size32 bits (4 octets)128 bits (8 groups of 16 bits)
Total Addresses~4.3 billion~340 undecillion
NotationDotted decimalHexadecimal colon-separated

This guide focuses primarily on IPv4 because it's where subnetting, gateway, and routing concepts are most commonly taught and used in enterprise environments.

Why Does It Exist?

Every device on a network needs a way to be identified. When your browser requests a web page, the server needs to know where to send the response back. The IP address solves this — it provides a structured, hierarchical addressing system so routers can efficiently move packets across the internet.

Analogy

Think of a phone call. You dial a number (the IP address) and the phone network routes your call to the right person. Without the number, the network has no idea where to connect you. IP works the same way for data packets.

Structure of an IPv4 Address

An IPv4 address has 32 bits, written as four decimal numbers separated by dots. Each number is called an octet (8 bits = 1 byte). Each octet ranges from 0 to 255.

  192  .  168  .   1   .  10
  ───     ───     ───     ──
  1st     2nd     3rd     4th
 octet   octet   octet   octet

In binary:
  11000000 . 10101000 . 00000001 . 00001010
  ────────   ────────   ────────   ────────
   8 bits     8 bits     8 bits     8 bits
                                            = 32 bits total

Static vs Dynamic

Static IP: Manually configured, doesn't change. Used for servers, network printers, routers. You set it yourself in the OS or device config.

Dynamic IP: Automatically assigned by a DHCP server (Dynamic Host Configuration Protocol). Most end-user devices (laptops, phones) get dynamic IPs. The DHCP server hands out an IP from a defined pool, along with the subnet mask, gateway, and DNS servers.

Chapter 02

Binary Math — The Foundation

You cannot understand subnetting without understanding binary. Every IP address, every subnet mask — it's all binary under the hood. The decimal notation (192.168.1.0) is just a human-friendly representation.

Binary Place Values

Each bit position has a value based on powers of 2:

Bit position:    7      6      5      4      3     2     1     0
Power of 2:     2⁷     2⁶     2⁵     2⁴     2³    2²    2¹    2⁰
Value:         128     64     32     16      8     4     2     1

Decimal to Binary Conversion

To convert a decimal number (like 192) to binary, check each power of 2 from left to right. If the value fits, write a 1 and subtract; otherwise write a 0.

Worked Example — Convert 192 to Binary
Start: 192

128 fits into 192?  YES → bit = 1,  remainder = 192 - 128 = 64
 64 fits into 64?   YES → bit = 1,  remainder =  64 -  64 =  0
 32 fits into 0?    NO  → bit = 0
 16 fits into 0?    NO  → bit = 0
  8 fits into 0?    NO  → bit = 0
  4 fits into 0?    NO  → bit = 0
  2 fits into 0?    NO  → bit = 0
  1 fits into 0?    NO  → bit = 0

Result: 192 in binary = 1 1 0 0 0 0 0 0
Worked Example — Convert 10 to Binary
Start: 10

128 fits? NO → 0     remaining: 10
 64 fits? NO → 0     remaining: 10
 32 fits? NO → 0     remaining: 10
 16 fits? NO → 0     remaining: 10
  8 fits? YES → 1    remaining: 10 - 8 = 2
  4 fits? NO → 0     remaining: 2
  2 fits? YES → 1    remaining: 2 - 2 = 0
  1 fits? NO → 0     remaining: 0

Result: 10 in binary = 0 0 0 0 1 0 1 0

Binary to Decimal Conversion

Add up the values of all positions where the bit is 1.

Example — 11000000 to Decimal
Bit:     1    1    0    0    0    0    0    0
Value: 128   64   32   16    8    4    2    1

Sum = 128 + 64 = 192

Full IP Address in Binary

IP:  192  .  168  .   1   .  10

     11000000 . 10101000 . 00000001 . 00001010
Key Insight

Each octet has exactly 8 bits. The maximum value for an octet is 11111111 = 128+64+32+16+8+4+2+1 = 255. That's why IP octets range from 0 to 255.

Chapter 03

Subnetting — What, Why, and How

What Is a Subnet?

A subnet (subnetwork) is a logical division of a larger network into smaller, more manageable pieces. Every IP address has two parts:

   ┌─────────────────────┬──────────────────┐
   │    Network Part     │    Host Part     │
   │  (identifies the    │  (identifies the │
   │   network/subnet)   │   specific       │
   │                     │   device)        │
   └─────────────────────┴──────────────────┘

The subnet mask defines where the boundary sits between the network and host portions.

Why Subnetting Exists

The 5 Reasons

1. Network Segmentation: Divide a large flat network into isolated segments. The accounting team doesn't need to see engineering's traffic.

2. Broadcast Control: Every subnet is a broadcast domain. Without subnetting, a broadcast from one device reaches EVERY device — causing congestion on large networks.

3. Security: Subnets allow firewall rules between segments. You can restrict database servers from being reachable by guest WiFi.

4. Efficient IP Usage: Don't waste a /16 (65,534 IPs) on an office with 20 people. Use a /27 (30 IPs) instead.

5. Routing Efficiency: Routers work with network addresses, not individual hosts. More subnets = more granular routing control.

The Subnet Mask

The subnet mask is a 32-bit number that "masks" the IP address to reveal the network portion. Bits set to 1 = network part, bits set to 0 = host part.

IP Address:   192.168.1.10     = 11000000.10101000.00000001.00001010
Subnet Mask:  255.255.255.0    = 11111111.11111111.11111111.00000000
                                  ├── network (24 bits) ──┤├ host ─┤

AND operation (bitwise):
  11000000.10101000.00000001.00001010  (IP)
& 11111111.11111111.11111111.00000000  (Mask)
= 11000000.10101000.00000001.00000000  → 192.168.1.0 (Network Address)

Why Usable Hosts = Total - 2

In every subnet, two addresses are reserved:

Network Address (first IP, all host bits = 0): Identifies the subnet itself. Example: 192.168.1.0/24

Broadcast Address (last IP, all host bits = 1): Sends to all devices in the subnet. Example: 192.168.1.255/24

How to Calculate: Step-by-Step

Problem: Given 192.168.1.10/24, find Network, Broadcast, Usable Range
Identify the mask. /24 means 24 network bits → subnet mask = 255.255.255.0. Host bits = 32 - 24 = 8 bits.
Find the Network Address. Set all host bits to 0. Since /24, the last octet is all host bits → 192.168.1.0
Find the Broadcast Address. Set all host bits to 1. Last octet = 11111111 = 255 → 192.168.1.255
Find the Usable Range. First usable = Network + 1 = 192.168.1.1. Last usable = Broadcast - 1 = 192.168.1.254
Count usable hosts. 2^8 - 2 = 256 - 2 = 254 usable hosts
Harder Problem: Given 10.50.100.130/18, find everything
Identify the mask. /18 = 18 network bits. Mask = 255.255.192.0
Why 192? → 18 bits total. First two octets = 16 bits (all 1s). We need 2 more bits from the 3rd octet.
3rd octet: 11000000 = 128 + 64 = 192. Remaining = all 0.
Host bits = 32 - 18 = 14 bits.
Find the block size. In the 3rd octet, the mask is 192. Block size = 256 - 192 = 64.
Subnets in the 3rd octet start at: 0, 64, 128, 192...
Our 3rd octet is 100. The largest multiple of 64 that is ≤ 100 is 64.
Network Address: 10.50.64.0
(3rd octet snaps down to 64, 4th octet = 0)
Next subnet starts at: 10.50.128.0
So broadcast = 10.50.127.255 (one IP before the next subnet)
Usable range: 10.50.64.1 → 10.50.127.254
Usable hosts = 2^14 - 2 = 16,384 - 2 = 16,382

The Magic Shortcut: Block Size Method

Quick Calculation

Block size = 256 - (subnet mask value in the interesting octet)

The "interesting octet" is the one where the mask is neither 255 nor 0.

Subnets start at multiples of the block size in that octet.

/25 → 255.255.255.128 → block = 256-128 = 128 → subnets: .0, .128
/26 → 255.255.255.192 → block = 256-192 =  64 → subnets: .0, .64, .128, .192
/27 → 255.255.255.224 → block = 256-224 =  32 → subnets: .0, .32, .64, .96, .128...
/28 → 255.255.255.240 → block = 256-240 =  16 → subnets: .0, .16, .32, .48, .64...
/29 → 255.255.255.248 → block = 256-248 =   8 → subnets: .0, .8, .16, .24, .32...
/30 → 255.255.255.252 → block = 256-252 =   4 → subnets: .0, .4, .8, .12, .16...
Chapter 04

CIDR Notation — /18, /24, /32 Explained

What Is CIDR?

CIDR (Classless Inter-Domain Routing, pronounced "cider") is the modern way to express an IP address and its associated subnet. The number after the slash tells you how many bits are used for the network portion.

192.168.1.0 /24
            ───
            └─ 24 bits for network, remaining 8 bits for hosts

10.0.0.0 /8
          ──
          └─ 8 bits for network, remaining 24 bits for hosts

Understanding Every CIDR from /0 to /32

The Formula

Total addresses = 2^(32 - prefix)

Usable hosts = 2^(32 - prefix) - 2

Higher prefix number → smaller subnet → fewer hosts. Lower prefix → larger subnet → more hosts.

Visual: How prefix length splits the bits

/8   NNNNNNNN.HHHHHHHH.HHHHHHHH.HHHHHHHH   2²⁴ = 16,777,216 IPs
/16  NNNNNNNN.NNNNNNNN.HHHHHHHH.HHHHHHHH   2¹⁶ =     65,536 IPs
/18  NNNNNNNN.NNNNNNNN.NNHHHHHH.HHHHHHHH   2¹⁴ =     16,384 IPs
/24  NNNNNNNN.NNNNNNNN.NNNNNNNN.HHHHHHHH   2⁸  =        256 IPs
/27  NNNNNNNN.NNNNNNNN.NNNNNNNN.NNNHHHHH   2⁵  =         32 IPs
/30  NNNNNNNN.NNNNNNNN.NNNNNNNN.NNNNNNHH   2²  =          4 IPs
/32  NNNNNNNN.NNNNNNNN.NNNNNNNN.NNNNNNNN   2⁰  =          1 IP

N = Network bit (fixed)    H = Host bit (variable)

Supernetting / Aggregation (CIDR in reverse)

CIDR also lets you combine multiple smaller subnets into a single larger one (called route summarization or supernetting).

Instead of advertising 4 separate /24 routes:
  10.1.0.0/24
  10.1.1.0/24
  10.1.2.0/24
  10.1.3.0/24

You can advertise 1 summary route:
  10.1.0.0/22      ← covers all four /24s

This reduces routing table size and improves router performance.
Chapter 05

Gateways and Routing

What Is a Gateway?

A gateway (specifically, a default gateway) is the IP address of the router that your device sends traffic to when the destination is outside your local subnet. It's your "exit door" to other networks and the internet.

Analogy

You live in an apartment building (your subnet). If you want to talk to your neighbor (same subnet), you just walk down the hall. If you want to visit someone in another building (different subnet), you must go through the main entrance (the gateway) and take the road (the routing infrastructure).

Your PC: 192.168.1.10/24
Gateway: 192.168.1.1         ← This is the router's interface on YOUR subnet

When you access google.com:
  - Destination: 142.250.190.14 (Google's IP)
  - Is 142.250.190.14 in 192.168.1.0/24? → NO
  - Send packet to default gateway (192.168.1.1)
  - Router takes it from there

What Is a Route?

A route is an entry in a routing table that tells the device (or router): "To reach network X, send the packet to Y via interface Z."

Viewing the Routing Table

# Linux
$ ip route show
default via 192.168.1.1 dev eth0 proto dhcp
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.10
10.10.0.0/16 via 192.168.1.254 dev eth0

# Windows
C:\> route print

# macOS
$ netstat -rn

Reading a Route Entry

  10.10.0.0/16 via 192.168.1.254 dev eth0
  ──────────── ─── ───────────── ─── ────
       │         │       │         │    │
       │         │       │         │    └─ Out through this interface
       │         │       │         └────── keyword
       │         │       └────────────── Next-hop router (gateway for this route)
       │         └────────────────────── keyword
       └──────────────────────────────── Destination network

Translation: "To reach anything in 10.10.0.0/16, send it to 192.168.1.254 through eth0"

How Routing Decisions Work

When your device wants to send a packet, it follows this process:

Check the destination IP. Where does this packet need to go?
Check the routing table. Is there a specific route for that destination network?
Longest Prefix Match. If multiple routes match, the most specific one wins (highest prefix number).
Example: A packet to 10.10.5.20 matches both 10.0.0.0/8 and 10.10.0.0/16. The /16 route wins because it's more specific.
Use the default route if nothing else matches. The default route (0.0.0.0/0) is the "catch all" — it matches everything. This points to your default gateway.
Critical Concept — Longest Prefix Match
Routing table:
  0.0.0.0/0       via 192.168.1.1     ← matches everything (lowest priority)
  10.0.0.0/8      via 10.0.0.1        ← matches all 10.x.x.x
  10.10.0.0/16    via 10.10.0.1       ← matches 10.10.x.x
  10.10.5.0/24    via 10.10.5.1       ← matches 10.10.5.x
  10.10.5.20/32   via 10.10.5.254     ← matches ONLY 10.10.5.20

Packet destined for 10.10.5.20 → uses the /32 route (most specific)
Packet destined for 10.10.5.99 → uses the /24 route
Packet destined for 10.10.99.1 → uses the /16 route
Packet destined for 10.99.1.1  → uses the /8 route
Packet destined for 8.8.8.8   → uses the /0 default route

Chapter 06

How Network Traffic Flows

The Complete Journey of a Packet

Let's trace what happens when you type https://google.com in your browser, from your laptop to Google's server and back. This involves every layer of the network stack.

Step 1: DNS Resolution

Browser → OS DNS Cache → DNS Resolver (e.g., 8.8.8.8) → Returns: 142.250.190.14

Your browser doesn't know what "google.com" means in terms of networking. It asks the DNS resolver to translate it into an IP address. This was covered in detail in your DNS guide.

Step 2: Is the Destination Local or Remote?

Your IP:    192.168.1.10  /24   → Network: 192.168.1.0
Destination: 142.250.190.14     → Network: 142.250.190.0 (different!)

192.168.1.0 ≠ 142.250.190.0 → Destination is REMOTE
→ Send to default gateway: 192.168.1.1

Step 3: ARP Resolution (Layer 2)

Your device knows the gateway's IP (192.168.1.1), but to send an Ethernet frame on the local network, it needs the gateway's MAC address.

Your PC → ARP Request (broadcast): "Who has 192.168.1.1? Tell 192.168.1.10"
Router  → ARP Reply (unicast):     "192.168.1.1 is at aa:bb:cc:dd:ee:ff"

Now your PC caches: 192.168.1.1 = aa:bb:cc:dd:ee:ff

Step 4: Packet Construction

Key Insight — MAC vs IP

MAC address changes at every hop. When the router receives your frame, it strips the Ethernet header, looks at the destination IP, finds the next hop, and creates a new Ethernet frame with the next router's MAC as destination.

IP address stays the same end-to-end (until NAT modifies it). The source and destination IP addresses remain constant throughout the journey.

Step 6: NAT (Network Address Translation)

Your home router performs NAT — it replaces your private source IP with its public IP before sending the packet to the internet.

OUTGOING (your PC → internet):
  Original:   Src=192.168.1.10   Dst=142.250.190.14
  After NAT:  Src=203.0.113.50   Dst=142.250.190.14
                   ↑ (router's public IP)

  Router records: 192.168.1.10:52431 ↔ 203.0.113.50:52431

INCOMING (internet → your PC):
  Arrives:    Src=142.250.190.14  Dst=203.0.113.50
  After NAT:  Src=142.250.190.14  Dst=192.168.1.10
                                       ↑ (translated back to your private IP)

Chapter 07

Network Topology

What Is Network Topology?

Network topology describes how devices (nodes) are arranged and connected in a network. There are two types:

Physical topology: How cables and hardware are physically laid out.

Logical topology: How data actually flows through the network (can differ from physical).

Common Topology Types

1. Star Topology ★

┌──────┐ │ PC1 │ └──┬───┘ │ ┌──────┐ ┌──┴───┐ ┌──────┐ │ PC2 ├──┤SWITCH├──┤ PC3 │ └──────┘ └──┬───┘ └──────┘ │ ┌──┴───┐ │ PC4 │ └──────┘

What: All devices connect to a central switch/hub.
Pros: Easy to manage, one device failure doesn't affect others, easy to add new devices.
Cons: Central switch is a single point of failure. If the switch dies, everything goes down.
Used in: Almost every modern office LAN. This is the most common topology today.

2. Mesh Topology

┌──────┐──────────────┌──────┐ │ R1 │ │ R2 │ └──┬───┘ └──┬───┘ │ ╲ ╱ │ │ ╲ ╱ │ │ ╲ ╱ │ │ ╲ ╱ │ ┌──┴───┐──────────────┌──┴───┐ │ R3 │ │ R4 │ └──────┘──────────────└──────┘

What: Every device connects to every other device (full mesh) or many others (partial mesh).
Pros: Maximum redundancy. Multiple path failures can be tolerated.
Cons: Expensive — number of links = n(n-1)/2 for full mesh.
Used in: WAN links between data centers, ISP backbone, critical infrastructure.

3. Hub-and-Spoke (Extended Star)

Branch Office 1 Branch Office 2 Branch Office 3 ┌─────────┐ ┌─────────┐ ┌─────────┐ │ Switch │ │ Switch │ │ Switch │ └────┬────┘ └────┬────┘ └────┬────┘ │ │ │ │ ┌──────────────┐ │ │ └──────┤ HQ Router ├──┘ │ │ (Hub) ├───────────────────────────┘ └──────────────┘

What: All remote sites connect to a central hub (HQ). Traffic between branches flows through HQ.
Pros: Centralized management, lower cost than full mesh.
Cons: Hub is a bottleneck and single point of failure. Branch-to-branch latency is doubled.
Used in: Enterprise WAN (VPN tunnels from branches to HQ).

4. Ring Topology

┌──────┐ │ R1 │ ╱──└──┬───┘──╲ ╱ │ ╲ ┌──┴───┐ ┌──┴───┐ │ R4 │ │ R2 │ └──┬───┘ └──┬───┘ ╲ │ ╱ ╲──┌──┴───┐──╱ │ R3 │ └──────┘

What: Devices connected in a circular loop. Data travels in one direction (or both in dual-ring).
Pros: Predictable performance, no collisions.
Cons: A single break kills the network (unless dual ring). Adding devices disrupts the ring.
Used in: SONET/SDH fiber rings, some industrial networks. Less common today.

5. Bus Topology (Legacy)

═══╤═══════╤═══════╤═══════╤═══════╤═══ │ │ │ │ │ ┌─┴─┐ ┌─┴─┐ ┌─┴─┐ ┌─┴─┐ ┌─┴─┐ │PC1│ │PC2│ │PC3│ │PC4│ │PC5│ └───┘ └───┘ └───┘ └───┘ └───┘

What: All devices share a single cable (the "bus"). Terminators at each end.
Pros: Cheap, simple.
Cons: One cable break = entire network down. Collisions. Terrible performance at scale.
Used in: Legacy 10BASE2/10BASE5 Ethernet. Basically extinct.

Chapter 08

How to Find Free (Available) IPs

Why You Need This

When adding a new server, printer, or device to a network, you need an IP that isn't already in use. Assigning a duplicate IP causes an IP conflict — both devices lose connectivity.

Method 1: DHCP (Automatic)

If your network uses DHCP, the DHCP server automatically tracks which IPs are leased and hands out free ones. Check the DHCP lease table on your router/server:

# On a Linux DHCP server (ISC DHCP):
$ cat /var/lib/dhcp/dhcpd.leases

# On Windows DHCP Server:
# Open DHCP Manager → Address Leases → see all active leases

# On most home routers:
# Web interface → DHCP → Client List

Method 2: Ping Sweep

Scan the subnet to see which IPs respond:

# Linux — sweep the entire /24:
$ for i in $(seq 1 254); do
    ping -c 1 -W 1 192.168.1.$i &>/dev/null && echo "192.168.1.$i is ALIVE"
  done

# Using nmap (much faster):
$ nmap -sn 192.168.1.0/24

# Output:
Nmap scan report for 192.168.1.1
Host is up (0.002s latency).
Nmap scan report for 192.168.1.10
Host is up (0.001s latency).
Nmap scan report for 192.168.1.50
Host is up (0.003s latency).

# IPs that DON'T appear in the output are likely free.

Method 3: ARP Table Check

# Show devices your machine has recently communicated with:
$ arp -a                    # macOS / older Linux
$ ip neigh show             # modern Linux

# Output:
192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
192.168.1.10 dev eth0 lladdr 11:22:33:44:55:66 REACHABLE

# Combine with ping sweep first for comprehensive results

Method 4: IPAM Tools (Enterprise)

In production environments, nobody does manual ping sweeps. You use an IPAM (IP Address Management) tool:

ToolTypeUse Case
InfobloxEnterprise (commercial)DNS + DHCP + IPAM integrated
BlueCatEnterprise (commercial)Large-scale DDI management
phpIPAMOpen sourceWeb-based, good for medium orgs
NetBoxOpen sourceNetwork source of truth, used by many data centers
Caution

A ping sweep may miss devices that have firewalls blocking ICMP. Some devices won't respond to ping even though they're using that IP. Always cross-reference with ARP tables and DHCP leases for accuracy.

$ ping 8.8.8.8                  # ping Google DNS
$ ping -c 4 192.168.1.1        # send exactly 4 pings (Linux/macOS)
$ ping -n 4 192.168.1.1        # send exactly 4 pings (Windows)

$ traceroute 8.8.8.8            # Linux/macOS (uses UDP)
$ traceroute -I 8.8.8.8         # Linux (uses ICMP, like Windows)
$ tracert 8.8.8.8               # Windows

# MTR — combined ping + traceroute (real-time):
$ mtr 8.8.8.8

$ dig google.com                # full DNS query

$ dig -x 8.8.8.8                # IP → hostname

# Check DNS cache (Windows):
C:\> ipconfig /displaydns
C:\> ipconfig /flushdns          # clear DNS cache

Quick Subnetting Formula Card

Formulas You Must Know
Total IPs in subnet          = 2^(32 - prefix)
Usable hosts                 = 2^(32 - prefix) - 2
Number of subnets possible   = 2^(prefix - original_prefix)
Block size (interesting oct) = 256 - mask_value_in_that_octet
Network address              = IP AND mask  (bitwise AND)
Broadcast address            = Network OR (NOT mask)  (bitwise OR with wildcard)
Wildcard mask                = 255.255.255.255 - subnet_mask
