📋 What is AWS?

🌍 AWS Global Infrastructure

AWS operates a massive global network. Understanding this infrastructure is essential — it forms the foundation for everything you'll learn.

Hierarchy of AWS Infrastructure

Key Concepts Breakdown

A Region is a geographic area with multiple isolated data centers. Examples: us-east-1 (N. Virginia), ap-southeast-1 (Singapore).

  • AWS has 30+ Regions worldwide
  • Each Region is completely independent — data doesn't leave a Region unless you configure it
  • Not all services are available in all Regions

How to choose a Region:

  • 🏛️ Compliance — Data sovereignty laws (e.g., GDPR requires EU Regions)
  • 📍 Proximity — Closer to users = lower latency
  • 💰 Pricing — Prices vary by Region
  • 🛠️ Service availability — New services launch in select Regions first

Each Region has minimum 3 AZs (usually 3-6). Each AZ is one or more discrete data centers.

  • AZs are physically separated — different buildings, different power grids, different flood plains
  • Connected via high-bandwidth, ultra-low-latency private networking
  • Deploying across AZs gives you high availability
  • AZ names (like us-east-1a) are randomized per account — your 1a might be my 1c

Edge Locations are mini data centers used by CloudFront (CDN) and Route 53 (DNS). There are 400+ edge locations — far more than Regions.

  • Cache content closer to users for low latency
  • Used by: CloudFront, Route 53, AWS WAF, AWS Shield

Local Zones are extensions of a Region placed closer to end users for ultra-low-latency needs (like gaming or video rendering).

AWS Wavelength — Deploys AWS compute/storage at 5G telecom provider edge locations for single-digit millisecond latency to mobile devices.

AWS Outposts — AWS-managed racks installed in YOUR data center. Same AWS APIs on-premises. Good for hybrid/low-latency/data residency needs.

📝
Exam Pattern: Questions often say "minimize latency" or "meet data residency requirements." Region choice = compliance + proximity. Multi-AZ = high availability. CloudFront = low latency for end users.

🌐 Global vs Regional vs AZ-Level Services

ScopeServices
GlobalIAM, Route 53, CloudFront, WAF, S3 (namespace is global, data is regional)
RegionalVPC, Lambda, API Gateway, RDS, DynamoDB, ELB
AZ-LevelEC2 instances, EBS volumes, Subnets, ENIs
⚠️
Common Mistake: S3 bucket names are globally unique, but the data is stored in the Region you choose. IAM is truly global — users/roles work across all Regions.

🏛️ AWS Well-Architected Framework

The Well-Architected Framework provides 6 pillars of best practices for building cloud architectures. This is one of the most heavily tested topics on the SAA-C03 exam.

🧠
Memory Aid — "CROPSS": Cost optimization, Reliability, Operational excellence, Performance efficiency, Security, Sustainability
🔒
Security
Protect data, systems, and assets. Implement least privilege, enable traceability, encrypt at all layers, automate security best practices.
🔄
Reliability
Recover from failures, meet demand dynamically. Test recovery procedures, scale horizontally, use Multi-AZ/Multi-Region.
⚡
Performance Efficiency
Use computing resources efficiently. Select right resource types, monitor performance, make trade-offs. Use serverless, caching, CDN.
💰
Cost Optimization
Avoid unnecessary costs. Right-size instances, use Spot/Reserved, analyze spending, implement lifecycle policies.
🔧
Operational Excellence
Run and monitor systems effectively. Automate changes, respond to events, use Infrastructure as Code, learn from failures.
🌱
Sustainability
Minimize environmental impact. Right-size workloads, use efficient hardware, reduce downstream waste. Newest pillar (added 2021).

Deep Dive: Each Pillar

Design Principles:

  • Implement a strong identity foundation — Centralize identity, use least privilege, use IAM roles (not keys)
  • Enable traceability — Log and audit all actions with CloudTrail, VPC Flow Logs
  • Apply security at all layers — Security Groups, NACLs, WAF, encryption
  • Automate security — Use Security Hub, GuardDuty, Config rules
  • Protect data in transit and at rest — TLS/SSL, KMS encryption, S3 bucket policies
  • Keep people away from data — Use automation, no direct access to production
  • Prepare for security events — Incident response plans, runbooks

Design Principles:

  • Automatically recover from failure — Auto Scaling, health checks, self-healing
  • Test recovery procedures — Game days, chaos engineering
  • Scale horizontally — Multiple small instances > one large instance
  • Stop guessing capacity — Use Auto Scaling, serverless
  • Manage change with automation — CloudFormation, CI/CD pipelines

Key Services: Multi-AZ RDS, S3 (11 nines durability), Route 53 health checks, Auto Scaling Groups

  • Democratize advanced technologies — Use managed services (RDS instead of self-managed DB)
  • Go global in minutes — Multi-Region deployments, CloudFront
  • Use serverless architectures — Lambda, Fargate, DynamoDB
  • Experiment more often — Test different instance types
  • Consider mechanical sympathy — Match your tech choice to your workload
  • Implement cloud financial management — Use Cost Explorer, Budgets
  • Adopt a consumption model — Pay for what you use, turn off when not needed
  • Measure overall efficiency — Track cost per transaction
  • Stop spending on undifferentiated heavy lifting — Use managed services
  • Analyze and attribute expenditure — Tagging strategy

Key Tools: AWS Cost Explorer, AWS Budgets, Reserved Instances, Savings Plans, Spot Instances

🤝 Shared Responsibility Model

One of the most important concepts for the exam. AWS and you (the customer) share security responsibilities.

Easy Rule of Thumb

If you can configure it in the AWS Console...Then it's YOUR responsibility
Security Groups, NACLs✅ You configure them = You own them
IAM users, policies, MFA✅ You create them = You secure them
EC2 OS patching✅ You choose the AMI = You patch it
S3 bucket policies✅ You set permissions = You're responsible

Managed vs Unmanaged — Responsibility Shifts

ServiceCustomer ResponsibilityAWS Responsibility
EC2 (IaaS)OS patching, firewall, IAM, data encryptionPhysical host, hypervisor, network
RDS (PaaS)IAM, data encryption, Security GroupsOS patching, DB engine patching, host
Lambda (Serverless)IAM, code, dataEverything else — OS, runtime, scaling
S3 (Managed)Bucket policies, encryption, IAM, data classificationInfrastructure, durability, availability
🎯
Exam Favorite: "Who is responsible for patching the OS on an EC2 instance?" → Customer. "Who is responsible for patching the OS on RDS?" → AWS. The more managed the service, the more AWS handles.

💰 AWS Pricing Fundamentals

AWS has a pay-as-you-go pricing model. Understanding how AWS charges is crucial for cost optimization questions on the exam.

3 Pricing Fundamentals

Compute
Pay per second/hour of compute time (EC2, Lambda invocations)
Storage
Pay per GB stored (S3, EBS, EFS)
Data Transfer
Pay per GB transferred OUT of AWS. Transfer IN is free. Transfer between AZs costs money.
🆓
Always Free: Data transfer IN to AWS is always free. VPC is free (but NAT Gateway, VPN, etc. cost money). IAM is always free. CloudFormation is free (you pay for resources it creates).
