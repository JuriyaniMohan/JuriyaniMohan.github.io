🖥️ AWS Compute Landscape

AWS offers compute services ranging from full control (EC2) to fully managed (Lambda). Your job is to pick the right one for each workload.

🖥️ EC2 — Elastic Compute Cloud

EC2 provides resizable virtual servers (instances) in the cloud. It's the backbone of AWS compute and the most heavily tested service on the exam.

EC2 Instance Naming Convention

Instance Family Types (Exam CRITICAL)

FamilyPrefixOptimized ForUse Cases
General Purposet, mBalanced CPU, memory, networkingWeb servers, dev environments, small DBs
Compute OptimizedcHigh-performance CPUsBatch processing, HPC, ML inference, gaming servers
Memory Optimizedr, x, zLarge in-memory datasetsIn-memory DBs (Redis), SAP HANA, real-time analytics
Storage Optimizedi, d, hHigh sequential read/write (local storage)Data warehousing, HDFS, distributed file systems
Accelerated Computingp, g, inf, trnGPU / hardware acceleratorsML training, video transcoding, 3D rendering
🧠
Memory Aid: Think "Dr. McGiftpx" — the first letters of instance families. Or simpler: C=Compute, M/R=Memory, T=Turbo (burstable), I/D=I/O (storage), P/G=GPU.

T-series Burstable Instances

t2, t3, t3a instances have a unique CPU credit model:

  • Baseline CPU performance (e.g., 20% of a vCPU)
  • Earn CPU credits when idle, spend them when bursting
  • If credits run out → performance drops to baseline
  • T2/T3 Unlimited — pay extra to burst beyond credits (no throttling, but $$)
⚠️
Exam Trap: If a question says "consistent high CPU" → do NOT pick t-series. Pick m or c family. T-series is for workloads with occasional spikes, not sustained load.

🔧 EC2 Launch & Configuration

What You Configure When Launching EC2

AMI
Amazon Machine Image — the OS template (Amazon Linux 2, Ubuntu, Windows, custom)
Instance Type
CPU + Memory combo (t3.micro, m5.xlarge, etc.)
Key Pair
SSH key for Linux or RDP password for Windows
Security Group
Virtual firewall — controls inbound/outbound traffic
User Data
Bootstrap script that runs ONCE at first launch (install packages, start services)
IAM Role
Instance Profile — permissions for the EC2 to access other AWS services

Security Groups (SG) — Key Rules

  • Act as a virtual firewall at the instance level
  • Stateful — if inbound is allowed, return traffic is automatically allowed
  • Only ALLOW rules — no deny rules. Anything not allowed is implicitly denied
  • Can reference another SG as source/destination (great for multi-tier architectures)
  • One instance can have up to 5 SGs
  • Default: all inbound BLOCKED, all outbound ALLOWED
💡
SG vs NACL (Preview): Security Groups are stateful + instance-level + allow-only. NACLs are stateless + subnet-level + allow AND deny. You'll get this comparison question on the exam.

EC2 Placement Groups

StrategyHow It WorksUse CaseRisk
ClusterAll instances on same rack, same AZHPC, low latency (10 Gbps between instances)If rack fails, all instances fail
SpreadEach instance on different hardware (max 7/AZ)Critical apps needing max isolationLimited to 7 instances per AZ
PartitionInstances in partitions on separate racks (up to 7 partitions/AZ)Hadoop, HDFS, Cassandra, KafkaPartition failure affects multiple instances
🎯
Exam Pattern: "Low latency between instances" → Cluster. "Isolate critical instances from each other" → Spread. "Big data distributed workload" → Partition.

🖼️ AMI — Amazon Machine Images

  • A template containing OS, software, configurations
  • Region-specific — must copy AMI to use in another Region
  • Types: AWS-provided (Amazon Linux, Ubuntu), Marketplace, Custom (you create)
  • Custom AMIs speed up boot time — pre-install all software, then launch from your AMI
  • Backed by EBS snapshots (stored in S3 behind the scenes)
💡
Exam Tip: "Reduce launch time for instances" → Use a custom AMI with everything pre-installed (called "golden AMI" pattern). This is faster than User Data scripts.

💰 EC2 Pricing Models (Exam Heavyweight)

This topic appears in nearly every practice exam. Master the trade-offs.

ModelDiscountCommitmentInterruption?Best For
On-Demand0%NoneNoShort-term, unpredictable workloads, testing
Reserved (RI)Up to 72%1 or 3 yearsNoSteady-state, predictable (databases, production servers)
Savings PlansUp to 72%1 or 3 years $/hrNoFlexible across families, regions, OS, tenancy
Spot InstancesUp to 90%NoneYES (2-min warning)Fault-tolerant: batch, CI/CD, data analysis, HPC
Dedicated Instances~Per-instance billingNoCompliance — no shared hardware
Dedicated Hosts~Per-host billingNoBYOL (Bring Your Own License), compliance, socket-based licensing
Capacity Reservations0%None (but reserves capacity)NoGuarantee capacity in an AZ for critical workloads

Reserved Instance Details

Standard RI — Up to 72% discount. Can change AZ, scope, instance size (within same family). Cannot change instance family, OS, or tenancy.

Convertible RI — Up to 66% discount. Can change instance family, OS, scope, tenancy. More flexibility, less discount.

Payment options: All Upfront (biggest discount) > Partial Upfront > No Upfront (least discount)

Scope: Regional (capacity across all AZs) or Zonal (specific AZ, guarantees capacity).

Savings Plans Details

Compute Savings Plans — Most flexible. Apply to EC2, Fargate, and Lambda. Can change instance family, Region, OS, tenancy. Up to 66% discount.

EC2 Instance Savings Plans — Commit to a specific instance family in a specific Region. Up to 72% discount. Can change size, OS, tenancy within that family.

You commit to a $/hr spend for 1 or 3 years. Usage above commitment is billed at On-Demand rates.

Spot Instances — Deep Dive

  • Define a max price you're willing to pay. If spot price exceeds it, instance is terminated or stopped.
  • 2-minute warning before interruption via instance metadata
  • Spot Fleets — collection of Spot + optionally On-Demand instances. Auto-selects cheapest instance types.
  • Spot Block (deprecated for new) — reserved Spot for 1-6 hours without interruption
🚫
NEVER use Spot for: Databases, critical applications, or anything that can't handle interruption. Use for: batch processing, image rendering, big data analytics, CI/CD builds, stateless web servers behind a load balancer.

Dedicated Host vs Dedicated Instance

FeatureDedicated InstanceDedicated Host
BillingPer-instancePer-host (entire physical server)
Visibility of hardwareNoYes (sockets, cores, host ID)
BYOL supportNoYes (server-bound licenses)
Affinity/placementNoYes (instance placement control)
🎯
Exam Key: "Bring Your Own License" or "per-socket licensing" → Dedicated Host. "Compliance — no shared tenancy" → Dedicated Instance OR Host.

💾 EC2 Storage Options

EBS (Elastic Block Store) — Network-Attached

  • Persistent block storage, like a virtual hard drive
  • Locked to one AZ — can't attach to instances in another AZ directly
  • Can be detached and reattached to another instance in the same AZ
  • Snapshots — backup an EBS volume to S3. Can copy snapshot to another Region.
  • Delete on Termination — root volume deletes by default; additional volumes don't

EBS Volume Types (Exam Favorite!)

TypeNameMax IOPSMax ThroughputUse Case
gp3General Purpose SSD16,0001,000 MB/sDefault for most workloads. IOPS & throughput set independently.
gp2General Purpose SSD16,000250 MB/sLegacy default. IOPS linked to volume size (3 IOPS/GB).
io2/io2 Block ExpressProvisioned IOPS SSD64,000 / 256,0001,000 / 4,000 MB/sDatabases, critical apps needing sustained high IOPS. Multi-attach capable.
io1Provisioned IOPS SSD64,0001,000 MB/sOlder gen of io2. Multi-attach capable (up to 16 instances).
st1Throughput Optimized HDD500500 MB/sBig data, data warehousing, log processing. NOT bootable.
sc1Cold HDD250250 MB/sInfrequently accessed data. Cheapest EBS. NOT bootable.
🎯
Exam Decision Tree: Need boot volume? → gp3/gp2/io2. Need >16,000 IOPS? → io2. Need cheap throughput? → st1. Need cheapest archive? → sc1. Can't boot from HDD types (st1/sc1)!

EBS Multi-Attach

Only available for io1 and io2 volumes. Attach a single EBS volume to up to 16 EC2 instances in the same AZ. Use case: clustered applications that need shared storage.

Instance Store — Ephemeral Storage

  • Physically attached to the host server (not network-attached like EBS)
  • Highest I/O performance — millions of IOPS
  • EPHEMERAL — data is LOST when instance stops, terminates, or hardware fails
  • Use for: temporary data, caches, buffers, scratch data
  • Cannot be detached or reattached
⚠️
Exam Pattern: "Highest possible disk I/O" → Instance Store. "Data must persist after instance stop" → EBS. "Data lost on termination is acceptable" → Instance Store is fine.

📸 EBS Snapshots

  • Point-in-time backup of an EBS volume, stored in S3
  • Incremental — only changed blocks are backed up
  • Can create volumes from snapshots in any AZ (migrate data across AZs!)
  • Can copy snapshots cross-Region for DR
  • EBS Snapshot Archive — move to cheaper tier (75% cheaper), 24-72h restore time
  • Recycle Bin — protect against accidental deletion (set retention 1 day to 1 year)
  • Fast Snapshot Restore (FSR) — no latency on first access ($$$)

⚖️ Elastic Load Balancing (ELB)

ELB distributes incoming traffic across multiple targets (EC2, containers, IPs, Lambda). It's a managed service — AWS handles scaling, availability, and maintenance.

ELB Types Comparison (Must Know)

FeatureALB (Application)NLB (Network)GWLB (Gateway)
LayerLayer 7 (HTTP/S)Layer 4 (TCP/UDP)Layer 3 (IP)
PerformanceGoodUltra-high (millions rps)High
Static IPNo (use with Global Accelerator)Yes (Elastic IP per AZ)No
RoutingURL path, hostname, headers, query stringsPort-basedIP-based
SSL TerminationYesYes (TLS)No
WebSocketYesYesNo
Target TypesEC2, IP, Lambda, containersEC2, IP, ALBEC2, IP
Use CaseHTTP APIs, microservices, web appsGaming, IoT, real-time, extreme perf3rd-party firewalls, intrusion detection
Sticky SessionsYesYesYes (flow hash)
🎯
Quick Decision: HTTP/microservices → ALB. Ultra-low latency / static IP / TCP → NLB. Third-party security appliances → GWLB. "Least operational overhead for web app" → ALB.

ALB Key Features

  • Target Groups — route to groups of targets based on rules
  • Path-based routing — /api/* → backend, /images/* → image servers
  • Host-based routing — app.example.com vs api.example.com
  • Sticky sessions — route same client to same target (cookie-based)
  • Cross-zone load balancing — enabled by default (free for ALB)
  • Connection draining (deregistration delay) — completes in-flight requests before removing target

📈 Auto Scaling Groups (ASG)

ASG automatically adjusts the number of EC2 instances based on demand. Combined with ELB, it creates self-healing, elastic architectures.

Scaling Policies

Policy TypeHow It WorksExample
Target TrackingSet a target metric, ASG adjusts to maintain it"Keep average CPU at 50%" — ASG adds/removes to match
Step ScalingDefine steps based on alarm thresholds"CPU > 70%: add 2. CPU > 90%: add 4"
Simple ScalingSingle action on alarm breach (legacy)"CPU > 70%: add 1 instance, wait 5 min cooldown"
Scheduled ScalingScale at specific times"Every Friday 5pm: set desired to 10 for weekend traffic"
Predictive ScalingML-based, predicts future traffic from patternsLearns your traffic pattern and pre-provisions instances
✅
Best Practice: Use Target Tracking as default — it's the simplest and most effective. Combine with Predictive Scaling for cyclical patterns. Use Scheduled for known events.

ASG Key Concepts

  • Launch Template (preferred) vs Launch Configuration (legacy, do not use)
  • Health checks: EC2 status checks (default) + optional ELB health checks
  • Cooldown period: Time to wait after scaling action before next action (default 300s)
  • Lifecycle Hooks: Pause instances during launch/termination for custom actions (install software, drain connections)
  • Instance Refresh: Rolling update to replace instances (e.g., when updating AMI)
  • Warm Pools: Pre-initialized instances in stopped state for faster scale-out

⚡ AWS Lambda — Serverless Compute

Lambda runs your code without provisioning servers. You upload code, AWS handles everything else. Pay only when your code executes.

Max Execution Time
15 minutes (900 seconds)
Memory
128 MB to 10,240 MB (10 GB)
Temp Storage (/tmp)
512 MB to 10,240 MB (10 GB)

50 MB zipped, 250 MB unzipped (use layers for more)

1,000 concurrent executions per Region (soft limit, can increase)
Pricing
$0.20 per 1M requests + compute time (GB-seconds). First 1M free!

Lambda VPC Access

  • By default, Lambda runs outside your VPC (has internet access)
  • To access VPC resources (RDS, ElastiCache), deploy Lambda in your VPC
  • Lambda in VPC loses internet access — needs NAT Gateway for internet
  • Uses ENI (Elastic Network Interface) in your VPC subnets
⚠️
Exam Favorite: "Lambda needs to access RDS in a private subnet AND call an external API" → Deploy Lambda in VPC with access to private subnet + use NAT Gateway in public subnet for internet access.

ECS Architecture

ECR — Elastic Container Registry

  • AWS-managed Docker registry (like Docker Hub, but private)
  • Store, manage, deploy container images
  • Integrated with ECS and EKS
  • Supports image vulnerability scanning
🎯
Exam Decision: "Run Docker containers with no server management" → Fargate. "Need Kubernetes" → EKS. "AWS-native container orchestration" → ECS. "Store Docker images" → ECR.

🧩 Other Compute Services

Elastic Beanstalk

  • PaaS — deploy web apps without managing infrastructure
  • Supports: Java, .NET, Node.js, Python, Go, Docker, etc.
  • Under the hood: creates EC2, ASG, ELB, RDS, etc.
  • Free — you only pay for underlying resources
  • Still gives you full control of resources if needed
  • Great for developers who don't want to manage infra

AWS Batch

  • Fully managed batch processing at any scale
  • Dynamically launches EC2 or Spot instances based on job requirements
  • You define jobs as Docker images, Batch handles scheduling & compute
  • Different from Lambda: no time limit, uses EC2 (not serverless in the Lambda sense)

AWS Lightsail

  • Simple, low-cost virtual servers for small projects
  • Bundled: compute + storage + networking at fixed monthly price
  • Great for simple web apps, blogs, dev/test environments
  • Not designed for enterprise or complex architectures
