LAB 1.1 Create IAM Users, Groups & Assign Policies
FreeBeginner
▼

🎯 Objective

Create IAM users, groups, assign managed policies, and test access with different permission levels.

📝 Steps

Create a Group for Developers

# Create a group called "Developers" aws iam create-group --group-name Developers # Attach AmazonEC2ReadOnlyAccess policy aws iam attach-group-policy \ --group-name Developers \ --policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess # Attach AmazonS3ReadOnlyAccess policy aws iam attach-group-policy \ --group-name Developers \ --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess

Create a Group for Admins

aws iam create-group --group-name Admins aws iam attach-group-policy \ --group-name Admins \ --policy-arn arn:aws:iam::aws:policy/AdministratorAccess

Create IAM Users and Add to Groups

# Create users aws iam create-user --user-name dev-alice aws iam create-user --user-name dev-bob aws iam create-user --user-name admin-carol # Add users to groups aws iam add-user-to-group --user-name dev-alice --group-name Developers aws iam add-user-to-group --user-name dev-bob --group-name Developers aws iam add-user-to-group --user-name admin-carol --group-name Admins # Create console login for dev-alice aws iam create-login-profile \ --user-name dev-alice \ --password 'TempPass123!' \ --password-reset-required

Verify Permissions

# List groups for a user aws iam list-groups-for-user --user-name dev-alice # List policies attached to group aws iam list-attached-group-policies --group-name Developers # Simulate: Can dev-alice launch EC2? aws iam simulate-principal-policy \ --policy-source-arn arn:aws:iam::$(aws sts get-caller-identity --query Account --output text):user/dev-alice \ --action-names ec2:RunInstances
Expected Result: dev-alice should have EC2 and S3 read-only access. The simulate call for ec2:RunInstances should return "implicitDeny" since she only has read-only.

🧹 Cleanup

aws iam remove-user-from-group --user-name dev-alice --group-name Developers aws iam remove-user-from-group --user-name dev-bob --group-name Developers aws iam remove-user-from-group --user-name admin-carol --group-name Admins aws iam delete-login-profile --user-name dev-alice aws iam delete-user --user-name dev-alice aws iam delete-user --user-name dev-bob aws iam delete-user --user-name admin-carol aws iam detach-group-policy --group-name Developers --policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess aws iam detach-group-policy --group-name Developers --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess aws iam detach-group-policy --group-name Admins --policy-arn arn:aws:iam::aws:policy/AdministratorAccess aws iam delete-group --group-name Developers aws iam delete-group --group-name Admins
LAB 1.2 Create Custom IAM Policy (JSON) & Test
FreeBeginner
▼

🎯 Objective

Write a custom IAM policy that allows S3 access to a specific bucket only, attach it to a user, and verify.

Create the Custom Policy JSON

cat << 'EOF' > s3-specific-bucket-policy.json { "Version": "2012-10-17", "Statement": [ { "Sid": "AllowListBucket", "Effect": "Allow", "Action": "s3:ListBucket", "Resource": "arn:aws:s3:::my-lab-bucket-12345" }, { "Sid": "AllowGetPutObjects", "Effect": "Allow", "Action": [ "s3:GetObject", "s3:PutObject" ], "Resource": "arn:aws:s3:::my-lab-bucket-12345/*" } ] } EOF

Create Policy in IAM

aws iam create-policy \ --policy-name S3SpecificBucketAccess \ --policy-document file://s3-specific-bucket-policy.json

Attach to a User and Test

# Get your account ID ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text) # Attach policy to user aws iam attach-user-policy \ --user-name dev-alice \ --policy-arn arn:aws:iam::${ACCOUNT_ID}:policy/S3SpecificBucketAccess # Simulate: Can user access the specific bucket? aws iam simulate-principal-policy \ --policy-source-arn arn:aws:iam::${ACCOUNT_ID}:user/dev-alice \ --action-names s3:GetObject \ --resource-arns arn:aws:s3:::my-lab-bucket-12345/test.txt
💡
Key Learning: Notice how the policy needs BOTH the bucket ARN (for ListBucket) AND the bucket/* ARN (for object-level actions). This is a common exam question.

🧹 Cleanup

aws iam detach-user-policy --user-name dev-alice --policy-arn arn:aws:iam::${ACCOUNT_ID}:policy/S3SpecificBucketAccess aws iam delete-policy --policy-arn arn:aws:iam::${ACCOUNT_ID}:policy/S3SpecificBucketAccess
LAB 1.3 Create IAM Role for EC2 & Assume It
FreeIntermediate
▼

🎯 Objective

Create an IAM Role that allows EC2 instances to read S3, and attach it to an EC2 instance (Instance Profile).

Create Trust Policy (who can assume the role)

cat << 'EOF' > ec2-trust-policy.json { "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Principal": { "Service": "ec2.amazonaws.com" }, "Action": "sts:AssumeRole" } ] } EOF

Create Role and Attach S3 Read Policy

# Create the role aws iam create-role \ --role-name EC2-S3-ReadOnly \ --assume-role-policy-document file://ec2-trust-policy.json # Attach S3 read-only policy aws iam attach-role-policy \ --role-name EC2-S3-ReadOnly \ --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess # Create Instance Profile (wrapper for EC2) aws iam create-instance-profile --instance-profile-name EC2-S3-ReadOnly-Profile aws iam add-role-to-instance-profile \ --instance-profile-name EC2-S3-ReadOnly-Profile \ --role-name EC2-S3-ReadOnly

Attach to an EC2 Instance (after launching)

# Associate with a running instance aws ec2 associate-iam-instance-profile \ --instance-id i-xxxxxxxxxxxx \ --iam-instance-profile Name=EC2-S3-ReadOnly-Profile # Verify from INSIDE the EC2 instance: # SSH into EC2, then run: aws s3 ls # Should work — no access keys needed!
🎯
Exam Connection: This is THE correct way to give EC2 instances access to AWS services. Never use access keys on EC2.

🧹 Cleanup

aws iam remove-role-from-instance-profile --instance-profile-name EC2-S3-ReadOnly-Profile --role-name EC2-S3-ReadOnly aws iam delete-instance-profile --instance-profile-name EC2-S3-ReadOnly-Profile aws iam detach-role-policy --role-name EC2-S3-ReadOnly --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess aws iam delete-role --role-name EC2-S3-ReadOnly

LAB 2.1Launch EC2 with User Data (Web Server Bootstrap)
FreeBeginner
▼

🎯 Objective

Launch an EC2 instance that auto-installs Apache web server on boot using User Data.

Create a Security Group allowing HTTP & SSH

# Get default VPC ID VPC_ID=$(aws ec2 describe-vpcs --filters "Name=isDefault,Values=true" --query "Vpcs[0].VpcId" --output text) # Create SG SG_ID=$(aws ec2 create-security-group \ --group-name web-server-sg \ --description "Allow HTTP and SSH" \ --vpc-id $VPC_ID \ --query 'GroupId' --output text) # Allow SSH (port 22) from your IP aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 22 --cidr $(curl -s ifconfig.me)/32 # Allow HTTP (port 80) from anywhere aws ec2 authorize-security-group-ingress --group-id $SG_ID --protocol tcp --port 80 --cidr 0.0.0.0/0

Create User Data Script

cat << 'EOF' > userdata.sh #!/bin/bash yum update -y yum install -y httpd systemctl start httpd systemctl enable httpd INSTANCE_ID=$(curl -s http://169.254.169.254/latest/meta-data/instance-id) AZ=$(curl -s http://169.254.169.254/latest/meta-data/placement/availability-zone) echo "<h1>Hello from EC2!</h1><p>Instance: $INSTANCE_ID</p><p>AZ: $AZ</p>" > /var/www/html/index.html EOF

Launch EC2 Instance

# Find latest Amazon Linux 2023 AMI AMI_ID=$(aws ec2 describe-images \ --owners amazon \ --filters "Name=name,Values=al2023-ami-2023*-x86_64" "Name=state,Values=available" \ --query "sort_by(Images, &CreationDate)[-1].ImageId" --output text) # Launch instance INSTANCE_ID=$(aws ec2 run-instances \ --image-id $AMI_ID \ --instance-type t2.micro \ --security-group-ids $SG_ID \ --user-data file://userdata.sh \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=WebServer-Lab}]' \ --query 'Instances[0].InstanceId' --output text) echo "Instance ID: $INSTANCE_ID"

Get Public IP & Test

# Wait for instance to be running aws ec2 wait instance-running --instance-ids $INSTANCE_ID # Get public IP PUBLIC_IP=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID \ --query 'Reservations[0].Instances[0].PublicIpAddress' --output text) echo "Visit: http://$PUBLIC_IP" # Open in browser — you should see "Hello from EC2!"
Expected: Browser shows "Hello from EC2!" with instance ID and AZ displayed.

🧹 Cleanup

aws ec2 terminate-instances --instance-ids $INSTANCE_ID aws ec2 wait instance-terminated --instance-ids $INSTANCE_ID aws ec2 delete-security-group --group-id $SG_ID
LAB 2.2EBS Volumes — Create, Attach, Snapshot, Restore
FreeBeginner
▼

🎯 Objective

Create an EBS volume, attach to EC2, write data, create snapshot, restore to a new volume.

Create gp3 EBS Volume

# Get the AZ of your running instance AZ=$(aws ec2 describe-instances --instance-ids $INSTANCE_ID \ --query 'Reservations[0].Instances[0].Placement.AvailabilityZone' --output text) # Create 10 GB gp3 volume in same AZ VOL_ID=$(aws ec2 create-volume \ --volume-type gp3 \ --size 10 \ --availability-zone $AZ \ --tag-specifications 'ResourceType=volume,Tags=[{Key=Name,Value=Lab-Data}]' \ --query 'VolumeId' --output text) # Wait and attach aws ec2 wait volume-available --volume-ids $VOL_ID aws ec2 attach-volume --volume-id $VOL_ID --instance-id $INSTANCE_ID --device /dev/xvdf

SSH into EC2 — Format & Mount

# On the EC2 instance: sudo mkfs -t xfs /dev/xvdf sudo mkdir /data sudo mount /dev/xvdf /data echo "Hello from EBS!" | sudo tee /data/test.txt cat /data/test.txt

Create Snapshot

SNAP_ID=$(aws ec2 create-snapshot \ --volume-id $VOL_ID \ --description "Lab snapshot" \ --query 'SnapshotId' --output text) aws ec2 wait snapshot-completed --snapshot-ids $SNAP_ID echo "Snapshot: $SNAP_ID"

Restore — Create New Volume from Snapshot

NEW_VOL=$(aws ec2 create-volume \ --snapshot-id $SNAP_ID \ --volume-type gp3 \ --availability-zone $AZ \ --query 'VolumeId' --output text) echo "New volume from snapshot: $NEW_VOL"
🎯
Exam Link: Snapshots let you migrate EBS across AZs and Regions. Create snapshot → copy to another Region → create volume from it there.

🧹 Cleanup

aws ec2 detach-volume --volume-id $VOL_ID aws ec2 wait volume-available --volume-ids $VOL_ID aws ec2 delete-volume --volume-id $VOL_ID aws ec2 delete-volume --volume-id $NEW_VOL aws ec2 delete-snapshot --snapshot-id $SNAP_ID
LAB 2.3Create Custom AMI (Golden Image)
FreeBeginner
▼

🎯 Objective

Install software on an EC2 instance, create a custom AMI, then launch a new instance from it.

SSH into your running EC2 and install software

sudo yum install -y nginx git sudo systemctl enable nginx sudo systemctl start nginx echo "Golden AMI works!" | sudo tee /usr/share/nginx/html/index.html

Create AMI from the instance

AMI_ID=$(aws ec2 create-image \ --instance-id $INSTANCE_ID \ --name "golden-ami-lab-$(date +%Y%m%d)" \ --description "Lab golden AMI with nginx" \ --no-reboot \ --query 'ImageId' --output text) echo "AMI: $AMI_ID" # Wait for AMI to be available (may take 2-5 minutes) aws ec2 wait image-available --image-ids $AMI_ID

Launch new instance from custom AMI

NEW_INST=$(aws ec2 run-instances \ --image-id $AMI_ID \ --instance-type t2.micro \ --security-group-ids $SG_ID \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=From-Golden-AMI}]' \ --query 'Instances[0].InstanceId' --output text) echo "New instance: $NEW_INST" # This instance boots with nginx already installed — no User Data needed!
Expected: New instance has nginx running immediately on boot — faster launch than User Data approach.

🧹 Cleanup

aws ec2 terminate-instances --instance-ids $NEW_INST aws ec2 deregister-image --image-id $AMI_ID # Also delete the snapshot created by the AMI aws ec2 describe-snapshots --filters "Name=description,Values=*$AMI_ID*" --query 'Snapshots[*].SnapshotId' --output text | xargs -I{} aws ec2 delete-snapshot --snapshot-id {}
LAB 2.4EC2 Instance Metadata & User Data Exploration
FreeBeginner
▼

🎯 Objective

Query EC2 instance metadata service (IMDS) to retrieve instance information.

SSH into EC2 and query IMDSv2

# Get token (IMDSv2 requires token-based access) TOKEN=$(curl -s -X PUT "http://169.254.169.254/latest/api/token" \ -H "X-aws-ec2-metadata-token-ttl-seconds: 21600") # Query metadata echo "Instance ID:" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id echo -e "\nInstance Type:" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-type echo -e "\nAvailability Zone:" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/placement/availability-zone echo -e "\nPublic IP:" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/public-ipv4 echo -e "\nIAM Role (if attached):" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/iam/security-credentials/ echo -e "\nUser Data:" curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/user-data
💡
Exam Note: IMDSv2 (token-based) is more secure than IMDSv1. AWS recommends enforcing IMDSv2 via --metadata-options HttpTokens=required. Metadata endpoint is always 169.254.169.254.

LAB 3.1S3 Bucket — Create, Upload, Versioning, Lifecycle
FreeBeginner
▼

🎯 Objective

Create S3 bucket, enable versioning, upload objects, configure lifecycle rules.

BUCKET="saa-lab-$(date +%s)-$(echo $RANDOM)" # Create bucket aws s3api create-bucket --bucket $BUCKET \ --region ap-southeast-1 \ --create-bucket-configuration LocationConstraint=ap-southeast-1 # Enable versioning aws s3api put-bucket-versioning --bucket $BUCKET \ --versioning-configuration Status=Enabled # Block public access (security best practice) aws s3api put-public-access-block --bucket $BUCKET \ --public-access-block-configuration \ BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true # Upload a file echo "Version 1" > test.txt aws s3 cp test.txt s3://$BUCKET/test.txt # Upload a second version echo "Version 2 - updated" > test.txt aws s3 cp test.txt s3://$BUCKET/test.txt # List versions aws s3api list-object-versions --bucket $BUCKET --prefix test.txt

Configure Lifecycle Rule

cat << EOF > lifecycle.json { "Rules": [ { "ID": "MoveToIA", "Status": "Enabled", "Filter": { "Prefix": "" }, "Transitions": [ { "Days": 30, "StorageClass": "STANDARD_IA" }, { "Days": 90, "StorageClass": "GLACIER" }, { "Days": 365, "StorageClass": "DEEP_ARCHIVE" } ], "NoncurrentVersionTransitions": [ { "NoncurrentDays": 30, "StorageClass": "GLACIER" } ], "NoncurrentVersionExpiration": { "NoncurrentDays": 90 } } ] } EOF aws s3api put-bucket-lifecycle-configuration --bucket $BUCKET --lifecycle-configuration file://lifecycle.json aws s3api get-bucket-lifecycle-configuration --bucket $BUCKET
💡
Exam Link: Lifecycle rules are exam favorites. Know the transitions: Standard → Standard-IA (30 days min) → Glacier (90 days) → Deep Archive. Minimum 128KB and 30 days for IA transition.

🧹 Cleanup

# Must delete all versions first aws s3api list-object-versions --bucket $BUCKET --query '{Objects: Versions[].{Key:Key,VersionId:VersionId}, Quiet: `true`}' > del.json aws s3api delete-objects --bucket $BUCKET --delete file://del.json 2>/dev/null aws s3api list-object-versions --bucket $BUCKET --query '{Objects: DeleteMarkers[].{Key:Key,VersionId:VersionId}, Quiet: `true`}' > del2.json aws s3api delete-objects --bucket $BUCKET --delete file://del2.json 2>/dev/null aws s3api delete-bucket --bucket $BUCKET

LAB 3.3S3 Encryption — SSE-S3, SSE-KMS, Client-side
FreeIntermediate
▼

🎯 Objective

Upload objects with different encryption methods and set default encryption.

# Upload with SSE-S3 (AES-256) aws s3 cp test.txt s3://$BUCKET/encrypted-s3.txt --sse AES256 # Upload with SSE-KMS (AWS managed key) aws s3 cp test.txt s3://$BUCKET/encrypted-kms.txt --sse aws:kms # Set default encryption to SSE-S3 aws s3api put-bucket-encryption --bucket $BUCKET \ --server-side-encryption-configuration '{ "Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}] }' # Verify encryption on an object aws s3api head-object --bucket $BUCKET --key encrypted-kms.txt \ --query 'ServerSideEncryption'
💡
Exam: SSE-S3 = AWS manages everything. SSE-KMS = You control the key (audit via CloudTrail, key rotation). SSE-C = You provide the key with every request. Default: all new buckets have SSE-S3 enabled.

🎯 Objective

Set up cross-region replication between two S3 buckets for disaster recovery.

SOURCE="saa-crr-source-$(date +%s)" DEST="saa-crr-dest-$(date +%s)" # Create source bucket (Singapore) aws s3api create-bucket --bucket $SOURCE --region ap-southeast-1 \ --create-bucket-configuration LocationConstraint=ap-southeast-1 aws s3api put-bucket-versioning --bucket $SOURCE --versioning-configuration Status=Enabled # Create destination bucket (different region — e.g., Tokyo) aws s3api create-bucket --bucket $DEST --region ap-northeast-1 \ --create-bucket-configuration LocationConstraint=ap-northeast-1 aws s3api put-bucket-versioning --bucket $DEST --versioning-configuration Status=Enabled # Create IAM role for replication (see AWS docs for full trust policy) # Then configure replication in the console: # S3 → Source bucket → Management → Replication rules → Create rule

LAB 5.3Security Groups vs NACLs — Side by Side
FreeIntermediate
▼

🎯 Objective

Create a NACL with explicit deny rules and test against Security Group behavior.

# Create a NACL for the public subnet NACL=$(aws ec2 create-network-acl --vpc-id $LAB_VPC --query 'NetworkAcl.NetworkAclId' --output text) # Allow inbound HTTP (rule 100) aws ec2 create-network-acl-entry --network-acl-id $NACL --rule-number 100 \ --protocol tcp --port-range From=80,To=80 --cidr-block 0.0.0.0/0 --rule-action allow --ingress # Allow inbound SSH (rule 110) aws ec2 create-network-acl-entry --network-acl-id $NACL --rule-number 110 \ --protocol tcp --port-range From=22,To=22 --cidr-block 0.0.0.0/0 --rule-action allow --ingress # Allow outbound ephemeral ports (required — NACLs are STATELESS!) aws ec2 create-network-acl-entry --network-acl-id $NACL --rule-number 100 \ --protocol tcp --port-range From=1024,To=65535 --cidr-block 0.0.0.0/0 --rule-action allow --egress # DENY a specific IP (block an attacker) aws ec2 create-network-acl-entry --network-acl-id $NACL --rule-number 50 \ --protocol -1 --cidr-block 203.0.113.0/24 --rule-action deny --ingress
🎯
Key Difference: SG = stateful (return traffic auto-allowed). NACL = stateless (must explicitly allow return traffic on ephemeral ports). NACL rules evaluated in order — lowest number first. First match wins.
