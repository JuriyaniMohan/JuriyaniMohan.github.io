S3 · EBS · EFS · Storage Gateway · Snow Family — Master every storage class, volume type, and data transfer strategy for the SAA-C03 exam and production architectures.

🗺️

Why Storage Matters on the SAA-C03

Storage questions make up roughly 20-25% of the exam. AWS doesn't just test "which service to use" — they test when to choose one storage class over another, how to optimize cost, how to design for durability vs. availability, and how to migrate data at scale.

🧠 The Architect's Mindset

When you see a storage question, always ask: (1) How much data? → (2) How is it accessed? (frequency, latency) → (3) Who/what accesses it? (single EC2? multiple? serverless?) → (4) Durability & availability requirements? → (5) Cost constraints?

🏗️ AWS Storage Decision Tree

📦 S3 — Object Storage

Unlimited storage of objects (files) up to 5TB each. Flat namespace with bucket/key structure. 11 9's durability. Perfect for: static assets, backups, data lakes, log storage.

~30% of storage questions

💾 EBS — Block Storage

Virtual hard drives attached to EC2. Persist independently from instance lifecycle. Supports snapshots to S3. Perfect for: databases, boot volumes, high-IOPS workloads.

~20% of storage questions

📁 EFS — File Storage

Managed NFS that multiple EC2 instances can mount simultaneously across AZs. Auto-scales. Perfect for: shared content repos, CMS, container storage, home dirs.

~15% of storage questions

Amazon S3 — Deep Dive

Why S3 Exists

Before S3, companies had to buy storage arrays, manage RAID, handle backups, and plan capacity months in advance. S3 gave you unlimited, 11-nines durable storage accessible via HTTP — pay only for what you use. It became the backbone of AWS: other services (CloudFront, Athena, EMR, Lambda) all integrate with S3 natively.

S3 Core Concepts

  • Bucket — Container for objects. Globally unique name. Region-specific.
  • Object — File + metadata. Key = full path (e.g., photos/2024/cat.jpg). Max size: 5TB.
  • Multipart Upload — Required for files >5GB, recommended for >100MB. Uploads parts in parallel.
  • Versioning — Keeps all versions of an object. Can't be disabled once enabled (only suspended).
  • S3 is NOT a file system — it's an object store. No directory structure — the "/" in keys is just a naming convention.

🎯 Exam Hot Spot

You WILL get 3-5 questions on choosing the right S3 storage class. The exam tests your ability to match access patterns → storage class → cost optimization. Memorize the retrieval times and minimum storage durations.

One Zone-IA: Only 1 AZ = if that AZ is destroyed, data is LOST. Only use for data you can recreate (thumbnails, processed logs). The exam loves to test this: "most cost-effective for data that can be re-generated" → One Zone-IA.

S3 Lifecycle Policies

Automating Cost Optimization

Lifecycle rules automatically transition objects between storage classes or expire (delete) them based on age. This is the #1 way to reduce S3 costs in production.

🔒

S3 Security Model

Access Control (4 Layers)

  1. IAM Policies — Attached to users/roles/groups. Control what API calls the principal can make.
  2. Bucket Policies — JSON resource-based policy on the bucket itself. Best for cross-account access and public access.
  3. ACLs (Legacy) — Object/bucket level. AWS recommends disabling. Exam answer: "use bucket policies instead."
  4. Block Public Access — Account-level guardrail. Overrides bucket policies & ACLs. Enable at the account level for security.

Encryption Options

  • SSE-S3 — AWS manages keys. Default encryption. No extra cost. Header: AES256
  • SSE-KMS — Uses AWS KMS. You control key rotation, audit via CloudTrail. Header: aws:kms. ⚠️ Has API call limits (throttling).
  • SSE-C — You provide the key with each request. AWS does NOT store your key. Must use HTTPS.
  • Client-Side — You encrypt before uploading. AWS sees only ciphertext.
🎯 Exam Tip

"Encrypt data and the company must manage their own keys, but don't want to manage the encryption process" → SSE-KMS. "Company provides and manages keys completely" → SSE-C.

🌐

S3 Advanced Features

Versioning

  • Enabled at the bucket level. Protects against accidental deletes and overwrites.
  • Delete = adds a "delete marker" (soft delete). Previous versions remain.
  • MFA Delete — requires MFA to permanently delete versions. Only root account can enable this.
  • Exam tip: "Protect against accidental deletion" → Enable versioning + MFA Delete.

Replication

  • CRR (Cross-Region) — Async copy to another region. Use for: compliance, DR, lower latency.
  • SRR (Same-Region) — Async copy within same region. Use for: log aggregation, live replication between prod/test.
  • Requires: versioning enabled on source AND destination.
  • Only NEW objects are replicated after enabling. Use S3 Batch Replication for existing objects.

S3 Transfer Acceleration

Uses CloudFront edge locations as on-ramp to S3. Users upload to nearest edge → AWS backbone network → S3 bucket. Best for: global uploads, large files, cross-continent transfers. Can achieve 50-500% speed improvement.

S3 Select & Glacier Select

Use SQL to retrieve only a subset of data from an object (e.g., CSV, JSON, Parquet). Up to 400% faster and 80% cheaper than downloading the entire object and filtering client-side. Replaced in many cases by Athena for more complex queries.

S3 Object Lock & Glacier Vault Lock

  • Object Lock — WORM (Write Once Read Many). Two modes:
    • Governance Mode — Only users with special permissions can delete/overwrite.
    • Compliance Mode — NO ONE can delete, not even root. Used for regulatory compliance.
  • Glacier Vault Lock — Similar WORM for Glacier. Once policy is locked, it can NEVER be changed.
  • Exam tip: "Regulatory requirement — data cannot be deleted for 7 years" → S3 Object Lock in Compliance mode OR Glacier Vault Lock.

S3 Event Notifications

Trigger actions when objects are created, deleted, restored, or replicated. Destinations:

  • Lambda — Process uploads (thumbnails, transcode, validation)
  • SQS — Queue events for downstream processing
  • SNS — Fan-out to multiple subscribers
  • EventBridge — Most flexible: supports filtering, multiple targets, replay. Recommended for new designs.
🏭 Production Architect Pattern

Data Lake on S3: Raw data lands in S3 Standard → Lifecycle to IA after 30d → Glacier after 90d. Athena queries data in-place. Glue Crawler auto-discovers schemas. Lake Formation manages permissions. This is the #1 architecture AWS pushes on the exam for analytics workloads.

Amazon EBS — Elastic Block Store

Why EBS Exists

EC2 instance store (local disk) is ephemeral — data is lost when the instance stops. EBS provides persistent, network-attached block storage that survives instance stops/starts. Think of it as a USB drive you can plug into any EC2 in the same AZ.

EBS Core Rules (Memorize These)

  • EBS volumes are AZ-locked — you can't attach a volume in us-east-1a to an EC2 in us-east-1b.
  • To move across AZs: Snapshot → Restore in new AZ.
  • To move across regions: Snapshot → Copy snapshot to new region → Restore.
  • Most volume types can attach to one EC2 only (exception: io1/io2 Multi-Attach).
  • EBS volumes are provisioned capacity — you pay for allocated size, not used space.
  • Delete on Termination: Root volume defaults to YES. Additional volumes default to NO. Exam tests this!
📊

EBS Volume Types — The Critical Table

🎯 Exam Hot Spot

You MUST know these volume types cold. The exam will describe a workload and expect you to pick the right volume type. Key decision: SSD for IOPS → gp3/io2, HDD for throughput → st1, Cold HDD for lowest cost → sc1.

Type Name Use Case Size Max IOPS Max Throughput Boot?
gp3 General Purpose SSD Default choice. Dev/test, small DBs, boot volumes 1 GiB – 16 TiB 16,000 1,000 MB/s ✅
gp2 General Purpose SSD (prev gen) Legacy. IOPS scales with volume size (3 IOPS/GiB) 1 GiB – 16 TiB 16,000 250 MB/s ✅
io2 Block Express Provisioned IOPS SSD Mission-critical DBs, SAP HANA, highest performance 4 GiB – 64 TiB 256,000 4,000 MB/s ✅
io1 Provisioned IOPS SSD High-perf DBs, latency-sensitive 4 GiB – 16 TiB 64,000 1,000 MB/s ✅
st1 Throughput Optimized HDD Big data, data warehouses, log processing 125 GiB – 16 TiB 500 500 MB/s ❌
sc1 Cold HDD Infrequent access, lowest cost 125 GiB – 16 TiB 250 250 MB/s ❌
⚠️ Critical Distinctions

gp3 vs gp2: gp3 lets you independently set IOPS and throughput (cost savings!). gp2 ties IOPS to size. Exam: "independent IOPS and throughput at lower cost" → gp3.

io2 Multi-Attach: Only io1/io2 support attaching to up to 16 EC2 instances simultaneously in the same AZ. Use case: clustered databases. Exam will specifically test this.

EBS Snapshots

How Snapshots Work

  • Point-in-time backup stored in S3 (managed by AWS — you can't see the bucket).
  • Incremental — only changed blocks since last snapshot are stored. Saves cost.
  • Can be used to create volumes in ANY AZ (same or different region).
  • Snapshots can be shared across accounts and copied across regions.
  • Fast Snapshot Restore (FSR) — pre-warms snapshot so no latency on first read. Costs extra. Exam tests this for "eliminate latency on first access from snapshot."

EBS Encryption

  • Uses AES-256 via KMS.
  • Encrypts: data at rest, in-flight between EC2 and EBS, snapshots, and volumes from snapshots.
  • Minimal latency impact.
  • To encrypt an unencrypted volume: Create snapshot → Copy snapshot with encryption → Create new volume from encrypted snapshot.

Amazon EFS & FSx — Shared File Systems

Why EFS Exists

EBS gives you a drive for ONE EC2. But what if 10 web servers need to read the same uploaded images? Or 50 containers need a shared config directory? EFS is a managed NFS that multiple instances mount simultaneously, across AZs. It auto-scales — no capacity planning needed.

EFS Core Features

  • Protocol: NFSv4.1 — works with Linux only (not Windows)
  • Multi-AZ: Accessible from any AZ in the region via mount targets
  • Auto-scaling: Grows/shrinks automatically. No provisioning.
  • Pricing: Pay per GB stored (no pre-provisioning). ~3x EBS cost per GB but no waste.
  • Performance modes: General Purpose (default, low latency) or Max I/O (high throughput, higher latency)
  • Throughput modes: Bursting (scales with size), Provisioned (fixed), Elastic (auto-scales with workload — recommended)

EFS Storage Classes

  • Standard — Multi-AZ, frequently accessed
  • Standard-IA — Multi-AZ, infrequent. Lower storage cost, retrieval fee.
  • One Zone — Single AZ, frequently accessed. 47% cheaper.
  • One Zone-IA — Single AZ, infrequent. Cheapest EFS option.
🎯 Exam Tip

"Linux shared storage across AZs" → EFS. "Windows shared storage" → FSx for Windows. "High-performance computing (HPC)" → FSx for Lustre.

🪟

Amazon FSx — Specialized File Systems

FSx for Windows File Server

  • Fully managed Windows-native file system (SMB protocol)
  • Supports Active Directory integration, ACLs, DFS namespaces
  • Multi-AZ deployment for HA
  • Use when: Windows EC2 need shared storage, or migrating on-prem Windows file shares
  • Supports both SSD and HDD storage options

FSx for Lustre

  • High-performance parallel file system for compute-intensive workloads
  • Sub-millisecond latencies, hundreds of GB/s throughput, millions of IOPS
  • Integrates with S3: Can read from/write to S3 transparently
  • Use when: Machine learning, HPC, video rendering, financial modeling
  • Deployment types: Scratch (temp, highest perf) or Persistent (long-term, replicated)

FSx for NetApp ONTAP

  • Fully managed NetApp file system
  • Multi-protocol: NFS, SMB, iSCSI
  • Supports snapshots, replication, cloning, compression, deduplication
  • Use when: Migrating workloads from on-prem NetApp, need multi-protocol access

FSx for OpenZFS

  • Managed ZFS file system
  • NFS protocol, up to 1 million IOPS, point-in-time snapshots
  • Use when: Migrating from on-prem ZFS, need ZFS features (snapshots, clones)
🎯 FSx Decision Matrix

Need SMB + Active Directory? → FSx for Windows.
Need HPC/ML performance + S3 integration? → FSx for Lustre.
Need multi-protocol (NFS+SMB+iSCSI)? → FSx for NetApp ONTAP.
Migrating from ZFS? → FSx for OpenZFS.

Snow Family & Storage Gateway

Why Snow Family Exists

Transferring 100TB over a 1 Gbps internet connection takes ~12 days. 1 PB takes ~4 months. AWS said: "We'll ship you a physical device. Load your data. Ship it back." It's literally faster to FedEx your data than upload it. That's the Snow Family.

Snowball Edge Compute 42 TB usable 52 vCPUs, 208 GB RAM, optional GPU Edge ML, processing in disconnected environments TBs

🎯 Snow Family Decision Rule

"Large data migration, limited bandwidth" → If data < 10 TB, just use DataSync over the internet. If 10TB-10PB → Snowball Edge. If >10 PB → Snowmobile. If edge compute needed → Snowball Edge Compute. If tiny + rugged → Snowcone.

AWS Storage Gateway

Why Storage Gateway Exists

Many companies can't do a "big bang" cloud migration. They need a bridge between on-premises storage and AWS. Storage Gateway runs as a VM on-prem and presents familiar storage protocols (NFS, SMB, iSCSI) while backing data to S3, EBS, or Glacier behind the scenes.

S3 File Gateway

  • Presents NFS/SMB interface to on-prem apps
  • Files stored as objects in S3
  • Local cache for low-latency access
  • Supports S3 Standard, IA, One Zone-IA
  • Use case: File shares backed by S3, migrating file data to cloud

Volume Gateway

  • Presents iSCSI block storage to on-prem
  • Cached mode: Primary data in S3, frequently accessed cached locally
  • Stored mode: Full data on-prem, async backup to S3 as EBS snapshots
  • Use case: Block storage with cloud backup

Tape Gateway

  • Virtual tape library backed by S3 + Glacier
  • Compatible with existing backup software (Veeam, NetBackup, etc.)
  • Use case: Replace physical tape libraries with cloud-backed virtual tapes
🎯 Storage Gateway Decision

"On-prem apps need file access backed by S3" → S3 File Gateway.
"On-prem backup software uses tapes" → Tape Gateway.
"On-prem apps need block storage with cloud backup" → Volume Gateway.
"Need to extend on-prem Windows file shares to AWS" → FSx File Gateway.

Exam Prep — Storage Questions

Question 1

A company stores application logs in S3 Standard. Logs are frequently accessed for the first 30 days, rarely accessed for the next 60 days, and must be retained for 7 years for compliance. The company wants to minimize storage costs. What should a Solutions Architect recommend?

✅ Answer: B
Lifecycle policies automate transitions to reduce cost as access frequency drops. Standard for first 30 days (frequent access), Standard-IA for days 30-90 (infrequent but still needs fast access), then Glacier Deep Archive for long-term compliance (cheapest, 12-48hr retrieval is acceptable for 7-year-old logs). One Zone-IA (A) risks data loss. Intelligent-Tiering (C) has monitoring fees and won't move to Glacier. Immediate Glacier (D) blocks access during the first 30 days when logs are needed.

Question 2

A database running on EC2 requires 64,000 IOPS of consistent performance. The database must be highly available and the storage must persist if the instance is terminated. Which storage solution meets these requirements?

✅ Answer: C
io2 supports up to 64,000 IOPS (or 256,000 with Block Express) and is persistent. Instance store (A) is ephemeral — data lost on termination. gp3 (B) maxes out at 16,000 IOPS. EFS (D) is file storage, not block storage, and doesn't provide the same IOPS guarantee for database workloads.

Question 3

A company needs to share files across multiple EC2 instances running Linux in three Availability Zones. The data includes frequently accessed application code and infrequently accessed log files. The solution must minimize costs. What should the architect recommend?

✅ Answer: C
EFS provides shared NFS across multiple AZs for Linux. Lifecycle management automatically moves infrequently accessed files to EFS-IA for cost savings. EBS Multi-Attach (A) only works within a single AZ and only with io1/io2. S3 (B) is object storage, not a POSIX file system — can't be natively mounted. FSx for Windows (D) uses SMB, not NFS — wrong protocol for Linux instances.

Question 4

A healthcare company must store medical records for 10 years. Regulations require that once stored, the data cannot be modified or deleted by anyone, including administrators. Which solution meets this requirement?

✅ Answer: B
Compliance mode Object Lock = NOBODY can delete the data, not even the root account, until the retention period expires. This is the WORM (Write Once Read Many) model required by healthcare/financial regulations. Governance mode (C) allows users with special permissions to override — doesn't meet the "no one can delete" requirement. MFA Delete (A) prevents accidental deletion but an admin with MFA can still delete. Bucket policies (D) can be changed by an admin.

Question 5

A company needs to migrate 50 TB of data from an on-premises data center to S3. The company has a 100 Mbps internet connection. The migration must be completed within 1 week. Which is the most appropriate solution?

✅ Answer: B
Math: 50 TB over 100 Mbps = ~46 days. That exceeds the 1-week requirement. Snowball Edge holds 80TB, can be shipped and loaded within a week. Transfer Acceleration (A) won't overcome the bandwidth limit. DataSync (C) still limited by the 100 Mbps pipe. Direct Connect (D) takes weeks/months to provision — won't help with the 1-week deadline.
📝 Key Exam Patterns for Storage
  • "Cost-effective long-term storage" → Glacier Deep Archive + lifecycle policy
  • "Data must never be deleted by anyone" → S3 Object Lock (Compliance) or Glacier Vault Lock
  • "Multiple EC2 need shared Linux storage" → EFS
  • "Highest IOPS for database" → io2 Block Express
  • "Migrate petabytes offline" → Snowball Edge or Snowmobile
  • "On-prem apps need seamless access to S3" → Storage Gateway (S3 File Gateway)
  • "HPC / ML file storage with S3 integration" → FSx for Lustre
  • "Windows shared storage with AD" → FSx for Windows File Server
